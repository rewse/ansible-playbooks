# MH-Z19 の UART 読み取りへの切り替え 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fox と hotel の MH-Z19 を PWM から UART（`/dev/ttyAMA0`）の読み取りに切り替え、PWM の配線とコードをなくす。

**Architecture:** mhz19 ロールに `serial` コンポーネントを足してシリアルコンソールを止め、`mhz192mqtt` の読み取りコマンドを UART に替える。コードはブランチ `feat/mhz19-uart` で用意し、PWM 出力が止まった fox を先に、続けて hotel を配線して適用し、両方が済んでから main に入れる。

**Tech Stack:** ansible-core、bash、`mh_z19`（PyPI）、Python `unittest`（`uv run --with pytest --with ansible-core pytest tests`）

**Spec:** `docs/superpowers/specs/2026-10-06-mhz19-uart-design.md`

## Global Constraints

- 作業はブランチ `feat/mhz19-uart` で行う。両ホストの切り替えが済むまで main に入れない。main の playbook を流すと、配線前のホストで publisher が UART に切り替わってしまうため
- 読み取りコマンドは `python3 -m mh_z19 --serial_device /dev/ttyAMA0 --serial_console_untouched`
- 両ホストの `cmdline.txt` にあるのは `console=serial0,115200` で、ファームウェアが起動時に `console=ttyAMA0,115200` へ書き換える。取り除く対象はこのどちらの表記でもよい。mask する unit は `serial-getty@ttyAMA0.service`
- `filter_co2`、`MAX_CO2=4900`、`MAX_STEP=200`、`STABLE_SPREAD=100` は変えない
- 再起動とシャットダウンは Ansible でしない。配線と電源操作はユーザーが行う。各ホストで `--check` なしの実行の前に差分を示して確認を取る
- 切り替えは fox、hotel の順。fox の PWM 出力は 2026-10-18 01:20 から止まっていて（GPIO12 が常に LOW、電源の入れ直しでも戻らない）、PWM と比べる手順は fox では使えない
- 実行は `--tags` で `mhz19_serial` または `mhz19_publisher` に絞る
- 手元の macOS には GNU grep（`grep -P`）がなく、publisher のテストは skip される。publisher のテストは fox で実行する（Task 1 Step 3 のコマンド）

## Review Focus

- UART が無応答（配線ミスやセンサー故障）で `mh_z19` が `{}` を返す: 3 回リトライしたあと `offline` を publish して非ゼロで終わり、`OnFailure` の通知が出る（Task 1 の `test_uart_no_response_publishes_offline`）
- 切り替え直後の UART 値が最後の採用値から 200 ppm を超えて離れている: 3 回そろうまで publish せず、3 回目で採用する（Task 1 の `test_level_change_is_accepted_after_three_agreeing_readings`）
- `cmdline.txt` のコンソール指定が `serial0` と `ttyAMA0` のどちらで書かれていても、その 1 語と後ろの空白だけが消え、ほかのパラメーターと 1 行の形は残る。2 回目は変更なし（Task 2 の check 差分）
- 再起動前は getty とカーネルコンソールが UART を握っている: `serial.yml` の handler が再起動が必要だと表示し、手順は再起動のあとに UART を読む（Task 3、Task 4）
- fox のセンサーが UART でも応答しない: 配線を確かめても `{}` が続く場合は、センサー本体の故障として切り替えを止め、交換をユーザーに伝える（Task 3 Step 4）

def test_reads_over_uart(self):
    result, calls, published = self.run_publisher(outputs=['{"co2": 650}'])

def test_uart_no_response_publishes_offline(self):

    self.assertNotEqual(result.returncode, 0)
    self.assertEqual(len(calls), 3)
    self.assertEqual(published[-1], ("mhz19/test_room/state", "offline"))

def test_level_change_is_accepted_after_three_agreeing_readings(self):
    self.write_state("600 600 600 600")
    for expected_published in (False, False, True):
        result, _, published = self.run_publisher(outputs=['{"co2": 900}'])
        self.assertEqual(result.returncode, 0)
        self.assertEqual(any(t.endswith("/co2") for t, _ in published), expected_published)

### Task 2: serial コンポーネントを足す（完了: `c8698fbc`）

**Files:**
- Create: `roles/mhz19/tasks/serial.yml`
- Modify: `roles/mhz19/tasks/main.yml`（publisher の前に import）、`roles/mhz19/handlers/main.yml`

**Interfaces:**
- Produces: タグ `mhz19_serial`。適用後の再起動で `/proc/cmdline` から `console=ttyAMA0,115200` が消え、`serial-getty@ttyAMA0.service` が masked になる。handler `Report a pending reboot for the UART`

- [x] **Step 1: `serial.yml` と handler を書く**

タスクは次の順で、名前は `serial | ...` にする。

1. `serial | Enable the UART`: `lineinfile`、path `/boot/firmware/config.txt`、regexp `'^enable_uart='`、line `enable_uart=1`、insertafter `'^\[all\]'`
2. `serial | Remove the serial console from the kernel command line`: `lineinfile`、path `/boot/firmware/cmdline.txt`、regexp `'^(.*?)console=(?:serial0|ttyAMA0),115200 ?(.*)$'`、line `'\1\2'`、backrefs `true`、notify `Report a pending reboot for the UART`。コメントには、ファームウェアが `serial0` を `ttyAMA0` に書き換えること、backrefs で一致しない行には何もしないこと、vfat がコロン入りのバックアップ名を受け付けないので `backup` を使えないことを書く
3. `serial | Mask the serial getty`: `ansible.builtin.systemd`、name `serial-getty@ttyAMA0.service`、masked `true`、state `stopped`

handler `Report a pending reboot for the UART` は `debug`、msg `"Reboot to release ttyAMA0 from the kernel console"`、verbosity `0`。`when: ... is changed` の task にすると ansible-lint の `no-handler` に引っかかるため、handler にする。

- [x] **Step 2: `main.yml` に import を足す**

publisher の前に `Import serial tasks`（`serial.yml`、tags `mhz19_serial`）を置く。publisher は UART が使える状態を前提にしているため、この順にする。
