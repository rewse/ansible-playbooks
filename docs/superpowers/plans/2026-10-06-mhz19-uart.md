# MH-Z19 の UART 読み取りへの切り替え 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fox と hotel の MH-Z19 を PWM から UART（`/dev/ttyAMA0`）の読み取りに切り替え、PWM の配線とコードをなくす。

**Architecture:** mhz19 ロールに `serial` コンポーネントを足してシリアルコンソールを止め、`mhz192mqtt` の読み取りコマンドを UART に替える。物理配線が必要なので、コードはブランチで用意し、hotel、fox の順に配線と適用を進めてから main に入れる。

**Tech Stack:** ansible-core、bash、`mh_z19`（PyPI）、pytest（`uv run --with pytest --with ansible-core pytest tests`）

**Spec:** `docs/superpowers/specs/2026-10-06-mhz19-uart-design.md`

## Global Constraints

- 作業はブランチ `feat/mhz19-uart` で行う。両ホストの切り替えが済むまで main に入れない。main の playbook を流すと、配線前のホストで publisher が UART に切り替わってしまうため
- 読み取りコマンドは `python3 -m mh_z19 --serial_device /dev/ttyAMA0 --serial_console_untouched`
- 取り除くカーネルパラメーターは `console=ttyAMA0,115200`。mask する unit は `serial-getty@ttyAMA0.service`
- `filter_co2`、`MAX_CO2=4900`、`MAX_STEP=200`、`STABLE_SPREAD=100` は変えない
- 再起動とシャットダウンは Ansible でしない。配線と電源操作はユーザーが行い、各ホストで `--check` なしの実行の前に差分を示して確認を取る
- 切り替えは hotel、fox の順
- 実行は `--tags` で `mhz19_serial` または `mhz19_publisher` に絞る

## Review Focus

- UART が無応答（配線ミス）で `mh_z19` が `{}` を返す: 3 回リトライしたあと `offline` を publish して非ゼロで終わり、`OnFailure` の通知が出る（Task 1 のテスト `test_uart_no_response_publishes_offline`）
- 切り替え直後の UART 値が PWM 時代の採用値から 200 ppm を超えて離れている: 3 回そろうまで publish せず、3 回目で採用する（Task 1 のテスト `test_level_change_is_accepted_after_three_agreeing_readings`）
- `cmdline.txt` の `console=ttyAMA0,115200` が行の途中にある: その語だけが消え、前後のパラメーターと 1 行の形が残る。2 回目は変更なし（Task 2 の check 差分の確認）
- 再起動前の getty が UART を握ったまま: `serial.yml` は再起動が必要だと表示し、手順は再起動のあとに UART を読む（Task 3、Task 4）
- `config.txt` に `enable_uart` がない: `[all]` の直後に `enable_uart=1` が入る。両ホストとも行があるので、実機では起きない（Task 2 の check 差分の確認で変更がないこと）

def test_reads_over_uart(self):

### Task 2: serial コンポーネントを足す

**Files:**
- Create: `roles/mhz19/tasks/serial.yml`
- Modify: `roles/mhz19/tasks/main.yml`（publisher の前に import）

**Interfaces:**
- Produces: タグ `mhz19_serial`。適用後の再起動で `/proc/cmdline` から `console=ttyAMA0,115200` が消え、`serial-getty@ttyAMA0.service` が masked になる

- [ ] **Step 1: `serial.yml` を書く**

タスクは次の順で、名前は `serial | ...` にする。

1. `serial | Enable the UART`: `lineinfile`、path `/boot/firmware/config.txt`、regexp `'^enable_uart='`、line `enable_uart=1`、insertafter `'^\[all\]'`
2. `serial | Remove the serial console from the kernel command line`: `lineinfile`、path `/boot/firmware/cmdline.txt`、regexp `'^(.*?) ?console=ttyAMA0,115200(.*)$'`、line `'\1\2'`、backrefs `true`、register `__mhz19_cmdline`。コメントに、backrefs により一致しない行には何もしないことと、vfat がコロン入りのバックアップ名を受け付けないため `backup` を使えないことを書く
3. `serial | Mask the serial getty`: `ansible.builtin.systemd`、name `serial-getty@ttyAMA0.service`、masked `true`、state `stopped`
4. `serial | Report a pending reboot`: `debug`、msg `"Reboot to release ttyAMA0 from the kernel console"`、verbosity `0`、when `__mhz19_cmdline is changed`

- [ ] **Step 2: `main.yml` に import を足す**

publisher の前に `Import serial tasks`（`serial.yml`、tags `mhz19_serial`）を置く。publisher は UART が使える状態に依存するため、この順にする。

### Task 3: hotel を切り替える

ユーザーの作業（電源と配線）を含む。各手順の前にユーザーへ伝え、終わったと言われてから次へ進む。

- [ ] **Step 1: `mhz19_serial` を適用する**

Task 2 Step 4 の差分を示して確認を取り、`--check` を外して実行する。続けてもう一度流し、`changed=0` を確かめる。

- [ ] **Step 2: ユーザーにシャットダウンと配線を頼む**

`sudo shutdown -h now` のあと、センサーの TX を GPIO15（ピン 10）に、RX を GPIO14（ピン 8）につなぐ。PWM 線は残す。

- [ ] **Step 3: 起動後の状態を確かめる**

Run: `ssh hotel.rewse.jp 'cat /proc/cmdline; systemctl is-enabled serial-getty@ttyAMA0.service; for i in 1 2 3; do sudo /opt/mhz19/bin/python3 -m mh_z19 --serial_device /dev/ttyAMA0 --serial_console_untouched; sudo /opt/mhz19/bin/python3 -m mh_z19 --pwm; done'`
Expected: cmdline に `console=ttyAMA0` がない。`masked`。UART が `{'co2': N}` を返し、PWM との差が正常時で数十 ppm 以内

- [ ] **Step 4: `mhz19_publisher` を適用する**

`--check --diff` の差分（読み取りコマンドの置き換え）を示して確認を取り、適用する。2 回目は `changed=0`。

- [ ] **Step 5: publish を確かめる**

Run: `ssh hotel.rewse.jp 'sudo systemctl start mhz192mqtt.service; systemctl is-failed mhz192mqtt.service; sudo journalctl -u mhz192mqtt.service --since -2min -o cat'`
Expected: `inactive`（成功）。`mcporter call home-assistant.ha_search query=dads_room_co2` の値が Step 3 の UART 値に近い

- [ ] **Step 6: ユーザーに PWM 線を外してもらう**

シャットダウン、GPIO12 の線を外す、起動。起動後に Step 5 をもう一度確かめる。
